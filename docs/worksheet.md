# 활동지 작성 자료

아래 내용은 이번에 제작·검증한 산출물을 설명한다. 학생 본인의 역할이나 실제 경험으로 바꾸려면 직접 실행하고 이해한 사실만 반영해야 한다.

## 1. 나의 역할과 실제로 한 일
이번에 준비한 자료는 웹 로그인 시스템의 SQL Injection 취약점을 비교하는 실습 프로그램, 처리 흐름도, 자동 실험 코드, CSV·JSON 결과표와 탐구 보고서이다. 프로그램과 문서 제작에는 Codex의 도움을 받았다. 학생이 직접 담당한 실행, 코드 분석, 결과 해석 및 발표 부분은 실제 수행 후 추가한다.

## 2. 탐구한 공학 원리
브라우저가 입력한 정보를 서버가 받아 데이터베이스와 비교하는 클라이언트-서버 구조를 다룬다. SQL 문자열에 입력을 직접 연결하면 입력이 명령문의 구조를 바꿀 수 있다. 매개변수화 쿼리는 명령문과 데이터를 분리한다. 이는 정보 과목의 프로그래밍, 조건 판단, 자료 처리 및 정보보호와 연결된다. 정확한 교과 단원명은 실제 교과서에 맞춰 확인한다.

## 3. 만드는 과정
설계에서는 입력 조건을 같게 두고 SQL 구성 방식만 바꾸도록 정했다. 제작에서는 로컬 서버와 메모리 데이터베이스, 두 로그인 함수를 구현했다. 실험에서는 8개 입력 조건을 두 방식에 적용해 16개 결과를 기록했다. 정상 사용자의 로그인 유지 여부와 인증 우회 차이를 함께 확인했다. 최초 학생 계획에서 실제로 변경한 사항은 확인되지 않았으므로 별도로 단정하지 않는다.

## 4. 실패와 극복 과정
재현 가능한 문제는 문자열 연결 방식에서 따옴표 입력이 쿼리 오류를 만들고, 인증 우회 입력은 잘못된 비밀번호로도 로그인에 성공한다는 점이다. 입력이 SQL 구문에 결합되는 코드를 원인으로 확인할 수 있다. 매개변수화 방식에서는 같은 우회 입력이 거부되고 정상 로그인이 유지된다. 이는 구현 간 비교 결과이며 학생의 실제 시행착오나 팀 논의를 증명하지 않는다. 직접 실험하면서 겪은 문제와 본인이 제안한 해결책이 있으면 이 항목에 추가한다.

## 5. 활동을 통해 달라진 생각과 진로 연계
직접 재현한 뒤 작성할 수 있는 성찰 질문: 정상 작동과 안전한 작동을 어떻게 구분하게 되었는가? 입력 차단과 쿼리 구조 분리의 차이를 설명할 수 있는가? 비밀번호 저장과 세션 보호 중 무엇을 더 탐구하고 싶은가? 이 활동이 컴퓨터공학 또는 정보보안 진로에 어떤 관심을 주었는가? 개인적인 생각과 진로는 본인이 실제로 느낀 내용으로 작성한다.
