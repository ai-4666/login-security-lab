# 탐구 보고서

## 연구 질문
로그인에서 사용자 입력을 SQL 명령문에 직접 연결하는 방식과 매개변수로 전달하는 방식은 같은 입력에 어떻게 다르게 반응하는가?

## 가설
정상 입력은 두 방식 모두 같은 결과를 내지만, SQL 구문에 영향을 주는 입력은 문자열 연결 방식에서 인증 조건을 우회할 수 있다. 매개변수화 방식은 해당 입력을 데이터로 처리하여 거부할 것이다.

## 실험 조건
Python 표준 라이브러리, SQLite, 가상 계정 1개를 사용했다. 독립변인은 SQL 구성 방식, 종속변인은 로그인 성공 여부와 오류 여부다. 계정 정보, 테스트 입력, 데이터베이스 구조는 동일하게 유지했다. 실제 사이트를 대상으로 실험하지 않았다.

## 방법
1. 로그인 입력·서버·데이터베이스의 흐름을 설계했다.
2. 문자열 연결 방식과 매개변수화 방식을 같은 프로그램에 구현했다.
3. 정상 계정, 오입력, 없는 사용자, 빈 아이디, 빈 비밀번호, 따옴표, 인증 우회 입력, 일반 이름의 따옴표 등 8개 조건을 각각 적용했다.
4. 성공 여부와 오류 상태를 CSV 및 JSON에 기록하고 예상 결과를 assertion으로 확인했다.

## 관찰 결과
정상 계정은 두 방식에서 성공했고 잘못된 비밀번호와 없는 사용자는 거부되었다. 빈 입력은 두 방식 모두 사전 검증에서 거부되었다. 취약한 방식에서는 따옴표 입력과 따옴표가 포함된 일반 이름으로 쿼리 오류가 발생했다. 개선한 방식은 같은 입력을 데이터로 처리하여 일반적인 인증 실패로 응답했다. 인증 우회 입력에서는 취약한 방식만 잘못된 비밀번호로 로그인이 성공했다.

## 해석
빈 입력 검증만으로는 SQL Injection을 방어할 수 없었다. 근본적인 차이는 명령문 구조와 사용자 데이터를 분리했는지에 있었다. 일부 문자 차단보다 매개변수화 쿼리를 적용하는 것이 이 실험의 원인을 직접 해결했다.

## 한계와 후속 탐구
8개 조건만으로 전체 보안을 증명할 수 없다. 속도·동시 접속·실서비스 환경은 측정하지 않았다. 후속 탐구에서는 비밀번호 해시 저장, 세션 관리, 로그인 시도 제한을 별도 변인으로 연구할 수 있다.
